# other/password.py: alternative_password_generator ignores the requested length when the required characters exceed it

**Expected behavior**

`alternative_password_generator(chars_incl, i)` should return a password whose length matches the requested length `i` (the `main()` prompt calls it "the max length of your password", and the comment above the function says `i = how many letters or characters the password length will be`).

**Actual behavior**

When `chars_incl` is longer than the requested length `i`, the subtraction `i -= len(chars_incl)` makes `i` negative, and the generator silently returns a password longer than what was asked for:

```
>>> from other.password import alternative_password_generator
>>> len(alternative_password_generator("abcdefgh", 5))   # asked for 5
8
>>> len(alternative_password_generator("abcd", 3))      # asked for 3
5
```

In the second case `i` becomes `-1`, so `quotient = i // 3` is `-1` and `remainder = i % 3` is `2` (Python's modulo of a negative number is positive), which adds one extra random letter on top of all the required characters.

**Steps to reproduce**

```
python - <<'EOF'
from other.password import alternative_password_generator
print(len(alternative_password_generator("abcdefgh", 5)))  # expected 5, prints 8
print(len(alternative_password_generator("abcd", 3)))      # expected 3, prints 5
EOF
```

**Suspected cause**

```
i -= len(chars_incl)
quotient = i // 3
remainder = i % 3
```

When `len(chars_incl) > i`, `quotient` goes negative while `remainder` stays positive, so `quotient + remainder` adds extra characters. Guarding the input (`if i < len(chars_incl): raise ValueError(...)` or clamping) would keep the generator honest about the requested length.
